# Правила проекта AI Interaction Enhancer

> Этот документ содержит правила и принципы, которых необходимо придерживаться при работе с проектом и при генерации ответов ИИ-ассистентами.

---

## Основные принципы

### 1. Фокус на пользователе
- Все решения принимаются с точки зрения удобства для необычных пользователей
- Приоритет - устранение трения между человеком и ИИ

### 2. Архитектурные решения
- Модульность: каждый компонент должен быть независимым
- Мультипровайдерность: поддержка OpenAI, Anthropic, локальных моделей
- Контекст - ключевой элемент: ИИ должен помнить важное между сессиями
- Экономичное использование ресурсов

### 3. Стиль разработки
- Итеративный подход: лучше работающий прототип, чем идеальная архитектура
- Минимализм: не добавлять функциональность без явной необходимости
- Документация: все ключевые решения должны быть задокументированы

### 4. Работа с ИИ-ассистентами
При генерации кода или ответов ИИ должен:
- Сверяться с этим файлом RULES.md
- Учитывать текущую стадию проекта (ранняя стадия, концепт)
- Избегать преждевременной оптимизации
- Не усложнять без необходимости
- Не навязывать конкретные технологии без обсуждения

### 5. Коммуникация
- Язык проекта: русский (основной), английский (для кода)
- Стиль: прямой, без воды, по существу

---

## Текущий статус проекта
- Стадия: Раннее исследование и концептуализация
- Стек: Не определен
- Приоритеты: Определение архитектуры, выбор стека, прототип

---

## Запрещенные паттерны
- Жесткие дедлайны и квартальные планы
- Over-engineering на ранних этапах
- Привязка к одному провайдеру без возможности замены
- Сложные абстракции без явной необходимости
